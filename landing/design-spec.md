# Photo to 3D — 落地页与移动端原型设计 Spec

版本：1.0 · 2026-10-03

产品依据：[现有项目](https://github.com/cain0624/photo-to-3d)。视觉参考：[Supaste](https://www.supaste.com/)。本文件将参考页面的视觉语法适配到照片转三维产品；参考网站的商标、产品图片、用户评价与商业数据不复用。

## 1、用户体验分析

### 用户与目标
- 首次访客：先理解“照片转空间”，再体验现成场景；无需在了解效果前配置 API。
- 照片创作者：选择自己的照片，了解生成条件与成本，提交任务并在完成后进入三维世界。
- 回访用户：从照片墙或本地存档继续探索，避免重复生成同一任务。

### 核心交互逻辑
落地页 → 原工作台 → 体验内置夕照湖岸；另一条路径为照片墙 → 选择照片 → 检查生成服务 → 提交生成 → 等待真实任务 → 场景就绪 → 三维漫游 → 保存引用。

生成失败保留原图并提供服务设置与重试入口。刷新后的恢复沿用原任务编号，不能静默重新发起收费请求。照片不可见区域由模型补全；不宣称扫描级精度。约三秒仅指场景就绪后的进入动画，不宣称“三秒生成”。

## 3、高保真 UI 设计

### 参考风格与适配规则
Supaste 的可见首屏使用高饱和蓝色至浅蓝色的纵向渐变、黑色紧凑导航、白色居中大标题、深色胶囊 CTA 与较大的产品展示。采用这些特征，内容全部围绕照片与空间展开。照片本身作为场景主视觉；不复制参考站的剪贴板图标、产品展示与评价。

落地页首屏：悬浮黑色导航 → 产品类别 → 两行大标题“拍下一刻。走进那一刻。” → 两行说明 → 主次 CTA → 三个真实能力标签 → 窗口式场景预览。

后续内容：混合尺寸的功能区 → 三步流程 → 常见问题 → 末尾体验入口。首屏渐变是参考驱动的明确色块主题；后续为浅色内容，夜间模式保留相应深色表面。

### 色彩 Token
| Token | 浅色值 | 深色值 | 用途 |
| --- | --- | --- | --- |
| --bg | #FAFAFA | #121316 | 页面背景 |
| --surface | #FFFFFF | #1B1D22 | 卡片与导航表面 |
| --soft | #F0F1F4 | #25272E | 次级分组 |
| --text | #16171A | #F5F6F8 | 正文 |
| --muted | #60636D | #A9ADB8 | 次级文本 |
| --line | #E2E4E9 | #353841 | 分隔与边框 |
| --accent | #3459D6 | #9BACFF | 应用动作与选中态 |
| --on-accent | #FFFFFF | #171C32 | 动作文字 |

首屏使用 #243AC0 → #0C8EFF → #BCEBFA 的蓝色渐变；导航 #08090D，首屏 CTA #101114 配白字。照片上的正文使用足够深的遮罩，玻璃只用于少量叠层标签。

### 字体与布局
- 系统字体：-apple-system、BlinkMacSystemFont、Helvetica Neue、PingFang SC、sans-serif；不强制依赖线上字体。
- 桌面标题 80–88 px，移动落地页 48–54 px，应用页标题 35 px，正文 14–17 px；正常说明不小于 12 px。
- 容器最大宽度 1160 px，桌面外边距 32 px，手机 20–24 px。
- 间距以 4/8 px 为基本节奏；章节间距桌面 110 px、手机 70 px。
- 页面卡片 24 px，图片 12–22 px，输入 12 px；按钮为胶囊。
- 手机画板采用 iPhone 16 Pro 的 402 × 874 CSS px；不是 1206 × 2622 的物理像素。
- 手机外壳圆角 52 px；顶部状态栏 59 px，模拟 Dynamic Island、时间与电量；底部 Tab Bar 留出手势区域。
- 此交付以 iOS 视觉为准。Android 落地开发沿用信息架构与 token，换成系统状态栏和 48 dp 触控目标，不把模拟 iOS 状态栏发布到真实网页。

### 交互与可访问性
- 所有触控目标至少 44 × 44 CSS px；Tab Bar、返回、收藏均有明确名称。
- 键盘可操作；保留焦点描边；图片有语义化 alt，装饰图标 aria-hidden。
- FAQ 使用原生 details；上传使用原生文件选择器；地址字段有独立 label。
- 上传限制 JPG/PNG/WebP、20 MB，选图后本地预览；无效输入就地报错。
- 动效仅用于按压反馈，150 ms；prefers-reduced-motion 禁用过渡。
- prefers-reduced-transparency 时用实色代替玻璃；不采用持续漂浮或自动播放轮播。

## 4、HTML 原型实现

HTML + Bootstrap 5.3.3 + Font Awesome 6.7.2 + 原生 CSS/JS。各页面独立文件，公共 styles.css 与 app.js。index.html 只组织 iframe 预览，不内联各页面内容。素材优先存于 assets/，便于静态部署。

独立落地页的 CTA 指向 https://cain0624.github.io/photo-to-3d/ 。导航锚点、FAQ、选图验证与预览、原型收藏、外观切换、后端地址格式验证均可交互。

### 原型边界
- 不修改或替换现有项目的 Three.js / Spark / Marble 逻辑。
- 场景页是照片视觉原型，真正三维漫游由 CTA 跳转至原项目。
- 生成页是等待界面示例，没有 API 调用，也不发起收费任务。
- 收藏与服务设置用独立 photo-design-* localStorage 键，仅供原型演示；真实项目继续用 IndexedDB 与原任务恢复机制。
- 用户照片只读取到本页内存用于预览，不上传到任何服务器。
- 无价格方案、用户评价或性能数字，因为没有相应事实依据。

## 5、开发接入要求

真实生成接入保留既有后端合约，API 密钥只在服务端。跨站服务使用 HTTPS、允许来源、认证与限流。静态 GitHub Pages 或 Vercel 前端不等于 Python 后端已经在线。

真实漫游保留相机、碰撞网格、出生点与人物移动逻辑。完成后再触发约三秒的空间进入动画，并给减弱动态用户提供即时进入。

上传接口返回任务 ID 时保存照片与任务引用；取消等待、刷新、重试均不得自动创建新收费任务。所有错误按实际响应区分配置缺失、网络故障、模型失败与资产加载失败。

## 6、验收要求

1. index.html 可平铺显示全部 8 个手机画板与独立落地页。
2. 1440 / 768 / 402 / 375 px 无页面级水平溢出；落地页自然响应式。
3. 图片、本地 CSS 与图标载入成功，状态栏和 Tab Bar 不遮挡核心操作。
4. 上传有效图片能预览；无图提交报错；类型与大小无效时可恢复。
5. 收藏后存档页有记录；无收藏时显示空状态。
6. FAQ 可键盘展开；明暗主题、减少动态均能正常显示。
7. 原型与真实功能边界清楚，无虚构生成进度与价格。
8. 本地验证完成后交付源码、页面截图与压缩包；发布到线上需选择目标项目并执行部署。

## 8、透明首屏与 DriftWall 照片墙（2026-10-03）

- 照片墙置于首屏蓝色渐变下方，颜色层改为 rgba：顶部不透明度 68%，中部 56%，下部 24%，最后淡出到页面背景。标题区域增加局部深色遮罩，保证白字辨识度。
- 顶部导航无底色、无边框、无背景模糊；桌面两侧留白 48 px，手机 20 px。照片卡片默认不透明度 84%。
- 用户提供 React Bits DriftWall 源码，当前 HTML 项目以原生 DOM/JS 适配，不引入 React 构建依赖。保持 7 列交错漂移、14 px/s 基础速度、0.45 速度差异、16° 俯仰、-14° 偏航、1200 px 透视与 120 px 深度。
- 桌面照片 230 × 154 px，间距 18 px；手机 174 × 124 px，间距 14 px；悬停抬升 18 px，所有列持续流动；视差减弱并增加缓动时间，避免停顿。
- 不提供播放／暂停按钮；不可见区域和后台标签停止帧循环；prefers-reduced-motion 显示静态墙，禁用视差。
- 背景照片为装饰性元素，aria-hidden，不产生重复 Tab 焦点。照片墙克隆卡片只复用 8 个本地文件。
- 8 张素材从 Unsplash 图片服务下载，保存于 assets/wall/；具体源地址记录于 sources.json。
- 此调整只影响 landing.html，手机功能原型与真实工作台保持原流程。
